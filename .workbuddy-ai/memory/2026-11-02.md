## Patient Lab Results module (frontend only)

Implemented the approved storyboard (`src/assets/Medora Lab Results Workflow Board.png`):
one Main page + one Details page with Results / Trends / Report / Related Visit tabs.

**Routes:** `/patient/lab-results`, `/patient/lab-results/[id]` (tab via `?tab=`).
Sidebar "Lab Results" was a coming-soon button → now links to the route.

**Data:** `src/lib/mock/labResults.ts` is a DERIVED layer over the existing
`medicalRecords.labResults` — it re-exports the same array (verified by identity),
so a test opened from Lab Results and from Medical Records is the same object.
No clinical fixtures were invented. 4 results: 3 Normal / 1 Abnormal.

**Key decisions:**
- Reference showed 8 tests incl. Blood Glucose; existing fixtures have 4. Did not
  fabricate results to match the mockup — counts derive from real data (4/3/1).
- Row badge vocabulary is the existing `LabStatus` (Normal/Abnormal); the card
  label "Need Attention" counts Abnormal. No new clinical statuses invented.
- Report: only CBC has an attached file (`f-cbc-report`, "CBC Lab Report.pdf").
  The PDF bytes do not exist, so View renders the report in-app and Download
  saves a clearly-labelled `.txt` copy. Other 3 results show the honest empty state.
- Trends: only CBC has history (WBC + Hemoglobin). 1Y/6M/3M windows → 3/2/1 points;
  single-point ranges are labelled instead of drawing a fake line.

**Verified:** tsc clean, `next lint` clean, `next build` OK (both routes),
35 data assertions pass (counts, identity with medicalRecords, filters, report
link, visit link, trend windowing, formatting).
**Not verified:** interactive browser click-through (no browser driver in this
environment; patient routes are behind RouteGuard anyway).

## Motion audit (same day)

Architecture is intact: `app/template.tsx` (root `.page-enter`), patient/admin
layouts animate only their content keyed by pathname, `RevealOnScroll` is the
single reveal mechanism (one-shot IntersectionObserver, progressive enhancement,
cleans its own attributes), landing sections use `motion/index.tsx` which is a
thin wrapper over the same component. No global transition suppression exists.

**Real bug found and fixed:** `[data-reveal="stagger"] > *:nth-child(n)` set
`transition-delay`, which applies to EVERY transitioned property — so a card in
position 6-8 ignored hover for up to ~350ms after the reveal. Replaced with a
`--reveal-child-delay` custom property applied only to opacity/translate; the
interaction properties keep 0ms.

**Likely causes for the user's report (not code defects):** OS-level
`prefers-reduced-motion` (globals.css deliberately makes everything instant), and
dev-mode per-route compilation making navigation feel like a reload.

**Env note:** `D:/med_backups` was wiped between sessions; `npm run build` trips
the sandbox bulk-delete guard when clearing `.next`. Workaround used: temporary
`distDir: ".next-build"` in next.config.mjs, then restore the config and move the
output outside the repo.
