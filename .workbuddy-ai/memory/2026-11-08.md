# 2026-11-08

## Phase 2 — Doctor My Schedule (frontend only)

Route: `/doctor/appointments` (dynamic, because dates anchor to the request day).

**Files**
- `src/lib/mock/doctorSchedule.ts` — `ScheduleAppointment` (PortalAppointment +
  `date`/`visitType`/`notes`), date helpers, and a deterministic generator that
  reuses `portalAppointments` verbatim for *today* so Overview and My Schedule
  never disagree. ~100 rows across ±16 days, Fridays closed.
- `src/components/doctor/schedule/` — DoctorSchedule (page state), ScheduleCalendar,
  ScheduleTable, ScheduleFilters (toolbar + chips + panel), AppointmentDetailsDialog,
  RescheduleDialog, RescheduleSuccessDialog.
- `DoctorOverlay` gained `size?: "md" | "xl"` (xl = 1000px) for the two-column
  quick view. Additive only; Overview still uses the default.
- Sidebar: "My Schedule" now links to the route. Overview "View Full Schedule"
  now routes there instead of a coming-soon toast.

**Workflow**: row/View → details dialog → (Start Consultation → existing
`/doctor/consultation/[id]`, View Patient Record → existing PatientQuickProfile,
Reschedule → dialog → success state → back, Mark Arrived (Upcoming only, demo),
Cancel (inline confirm, demo)).

**Honesty**: reschedule writes local state only; success copy says notification
needs backend integration; every dialog carries a demo-session note.

**Gotchas found while verifying**
- Opening Reschedule from the details dialog stacked two modals → added
  `rescheduleFrom` and close/reopen the details on cancel.
- Upcoming/Completed tabs span many days but the table had no date column →
  `showDate` prop adds the date under the time.
- Filter count now includes the date chip so the badge matches the chips.
- Calendar renders blank cells for out-of-month days and is capped at 360px when
  stacked below xl (it stretched full width before).

Verified with headless Chrome + a CDP step driver (`D:/med_backups/drive.mjs`)
at 1672 / 1024 / 390: overview, search, filters, details, reschedule validation,
success state, mark arrived, cancel confirm, start-consultation navigation.

## Phase 3 — Doctor Patients (frontend only)

Routes: `/doctor/patients` and `/doctor/patients/[patientId]` (`?tab=` deep-links).

**Data** — `src/lib/mock/doctorPatients.ts` wraps `portalPatients` instead of
duplicating identity: name/MRN/age/gender/allergies/conditions/medications/notes/
visits/labs all come from the existing fixtures, and only the extra depth (DOB,
address, follow-up date, structured meds, documents, condition group) is added
per id. So Overview, My Schedule and Patients can never disagree about a person.
All four summary cards are derived (`getPatientStats`), never hardcoded.

**Components** — `src/components/doctor/patients/`: DoctorPatients (page state),
PatientSummaryCards, PatientFilters (toolbar + chips + panel + two-thumb age
slider), PatientsTable (+ mobile card list + empty state), StartConsultationDialog,
FullPatientProfile (6 tabs), PatientProfileRoute (reads `?tab=` under Suspense).

**Reuse** — `PatientQuickProfile` was restyled to the storyboard (pill clinical
cards, notes block, teal View All, pill footer buttons) and is shared by Overview
and Patients. Overview's "View All" and Quick Profile footer now route into the
module instead of a coming-soon toast.

**Honesty** — Add Patient explains registration is a reception workflow; reschedule
and consultation handoff are local-only; document downloads are disabled with a
note (no fabricated files); Medical History is read-only.

**Gotchas**
- `fieldset` + `legend` nested inside a flex div is invalid and broke the filter
  panel layout — use plain divs.
- `parseMedication` must match the dose across two tokens ("5 mg"), otherwise the
  whole string became the name and the dose showed "—".
- Mobile profile header: give the action row `w-full sm:w-auto`, or the identity
  text collapses to one word per line.
- `/api/auth/me` returns 500 on every route in `next start` without the Express
  backend — pre-existing, not a Patients regression.
