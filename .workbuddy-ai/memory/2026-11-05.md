# 2026-11-05

## Doctor Portal — Phase 1: Overview (frontend only)

No `src/app/doctor/` existed before this. Created the Doctor Portal shell + the
Overview page and its attached UI states.

**Routes:** `/doctor/dashboard` (static), `/doctor/consultation/[id]` (dynamic
handoff prototype). Sidebar/topbar live in `src/app/doctor/layout.tsx`; only page
content animates (`.page-enter` keyed by pathname, same convention as patient shell).

**Files:** `src/lib/mock/doctorPortal.ts` (10 patients / 10 appointments),
`DoctorWorkspace.tsx` (session-scoped status overrides), `DoctorSidebar`,
`DoctorTopbar`, `overview/{OverviewSections,DoctorOverlay,AppointmentQuickView,PatientQuickProfile,DoctorOverview}.tsx`.
One modified file: `src/lib/role-home.ts` (doctor now lands on `/doctor/dashboard`
instead of `/workspace`).

**Key decisions:**
- Status vocabulary is doctor-specific (`Upcoming|Waiting|Arrived|In Progress|
  Completed|Cancelled`) because the patient union only has 3 values.
- All counts derive from the appointment array. "Waiting Patients" = Waiting +
  Arrived, which reconciles the reference's "4 waiting" with the donut (2 Waiting
  + 2 Arrived = 4 of 10). Alerts reuse PENDING_REPORTS/FOLLOW_UPS_DUE so cards and
  alerts never disagree.
- Fixtures were rebalanced so the compact schedule starts at 10:00 (Omar, Salma,
  Youssef, Mona) exactly like the storyboard: Nadia moved to Completed at 09:30,
  Huda became Waiting.
- "Mark Arrived" is deliberately NOT wired: doctors lack check-in permission
  (reception owns it). Button is muted + explains on click.
- Consultation Workspace is a scoped handoff only — no notes editor, recording,
  transcripts, AI reports, prescriptions or lab ordering.
- Drawer/modal share one `DoctorOverlay` with focus trap, Escape, scroll lock and
  focus restore (stable `onCloseRef` so parent re-renders don't steal focus).
